# Документация по проекту

## 1. Назначение и цели проекта
Проект представляет собой набор модулей для анализа туристических маршрутов и оценки их опасности по координатам и времени их прохождения. В состав входят:
- **Агенты** для очистки "грязного" датасета и обучения моделей машинного обучения.
- **Дэшборд** с аналитикой и визуализацией маршрутов.
- **API-сервис** для онлайн-предсказаний опасностей по координате.
- **Веб-приложение** для прогнозирования опасности на маршрутах по выбранной дате.

## 2. Архитектура проекта
### 2.1. Схема файлов
- **Данные**: `clear_data.db`, `info_table.csv`, `logs.csv`, GPX-треки и карты маршрутов.
- **Моделей**: `dangerous.joblib`, `fire.joblib`, `flood.joblib`, `evacuation.joblib`.
- **Сервис (API)**: FastAPI-приложение для точечных запросов опасности.
- **Визуализация**: Дэшборд (аналитика) и Dash-приложение прогнозов по маршрутам.

### 2.2. Роли агентов и их взаимодействие
Под «агентами» в контексте проекта подразумеваются классы, выполняющие свои функции:
- **Агент данных** — читает и готовит данные из SQLite/CSV, обеспечивает доступ к признакам.
- **Агент признаков** — формирует признаки из координат/времени и внешних источников (температура, высота, окружение).
- **Агент модели** — загружает модели `joblib`, выполняет прогнозы.
- **Агент визуализации** — отображает карты и графики для анализа и результатов прогнозов.

**Схема взаимодействия:**
1. Пользователь выбирает маршрут/дату (Dash) или отправляет координаты (FastAPI).
2. Агент данных получает исходные признаки из БД и формирует запросы к внешним API.
3. Агент признаков добавляет вычисленные признаки (температура, высота, окружение и т.д).
4. Агент модели выполняет прогноз.
5. Агент визуализации отображает результат (карта/графики) или отдаёт JSON-ответ.

## 4. Источники данных
### 4.1. SQLite БД
Файл `clear_data.db` содержит таблицу `Clear_data`, которая используется:
- в Dash-дэшборде (`Dash (Module_B)/main.py`);
- в Dash-приложении прогнозов (`Application (Module_D)/app.py`).

### 4.2. Описание полей (info_table.csv)
Файл `info_table.csv` содержит русскоязычное описание всех признаков (например, `track_id`, `point_id`, `time`, `latitude`, `longitude`, и др.).

### 4.3. Модели
В проекте используются предобученные модели в формате `joblib`:
- `dangerous.joblib` — общая опасность;
- `fire.joblib` — пожароопасность;
- `flood.joblib` — опасность наводнения;
- `evacuation.joblib` — эвакуация.

## 5. Модули

### 5.1. Веб-приложение прогнозов (Module_D/app.py)
**Назначение:** прогноз опасности на маршруте по выбранной дате, с визуализацией на карте.

**Ключевая логика:**
- Подключение к БД `clear_data.db` и подготовка данных.
- Для каждой точки маршрута формируется прогноз (используются модели `joblib` и модель временных рядов ARIMA для температуры).
- Итоговая карта строится через Plotly Mapbox и отображается в Dash.

### 5.2. API-сервис (Module_D/main.py)
**Назначение:** API для онлайн-прогнозов по одной точке (широта/долгота).

**Функциональность:**
- Запросы к Open-Meteo (температура и высота).
- Запросы к Overpass API (наличие воды, леса, зданий в радиусе 500 метров вокруг точки).
- Использование модели для прогноза опасностей.

**Эндпоинты:**
- `GET /get_common_dangerous/{lat}/{long}` — общая опасность точки.
- `GET /get_fire_dangerous/{lat}/{long}?time` — пожароопасность.
- `GET /get_flood_dangerous/{lat}/{long}?time` — риск наводнения.

### 5.3. Дэшборд аналитики (Module_B/main.py)
**Назначение:** визуальный анализ маршрутов и данных.

**Функции:**
- Средняя частота шагов по сезонам.
- Зависимость температуры от времени суток.
- Визуализация маршрутов на карте.
- Сравнение высоты и частоты шагов.

## 6. Запуск и настройка

### 6.1. Зависимости
Минимальный набор библиотек:
- `pandas`, `plotly`, `dash`, `fastapi`, `uvicorn`, `joblib`, `openmeteo-requests`, `requests`, `sqlite3`, `statsmodels`, `tqdm`, `geopy`.

Рекомендуется использовать виртуальное окружение:
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 6.2. Запуск Веб-приложения (Module_D/app.py)
```bash
python "Проект №6 (последний срез)/Application (Module_D)/app.py"
```
После запуска приложение будет доступно по адресу, указанному в логах Dash.

### 6.3. Запуск API-сервиса (Module_D/main.py)
```bash
python "Проект №6 (последний срез)/Application (Module_D)/main.py"
```
По умолчанию сервис стартует на `http://127.0.0.1:8000`.

### 6.4. Запуск Дэшборда (Module_B/main.py)
```bash
python "Проект №6 (последний срез)/Dash (Module_B)/main.py"
```

## 7. Важные замечания по переносимости
- В исходном коде используются **абсолютные пути Windows** (например, `C:\Users\...`). Для запуска в другой среде необходимо заменить пути на относительные или на конфигурируемые значения.
- API-запросы к Open-Meteo и Overpass требуют доступ в интернет.

## 8. Технологии
- **Python** (основной язык программирования).
- **Dash/Plotly** (веб-визуализация и интерактивные дэшборды).
- **FastAPI + Uvicorn** (API-сервис для предсказаний).
- **SQLite** (локальная база данных).
- **Pandas** (обработка данных).
- **Joblib** (хранение и загрузка моделей).
- **ARIMA** (прогноз температуры).
- **Open-Meteo API / Overpass API** (внешние источники признаков).
